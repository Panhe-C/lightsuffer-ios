# tools — reference fixture generator

`gen_fixtures.py` produces the original slice **reference fixtures** that the
Swift port (`Sources/FilmPhysics`) is validated against.
`gen_autoexposure_fixtures.py` separately produces the focused CPU auto-exposure
fixtures; it reuses the same format and base setup without regenerating or
changing the earlier slices.

The fixtures are generated by running the **unmodified upstream Python
engine** (`spektrafilm`, commit `3bb2c2d`), so they are ground truth, not a
re-implementation.

## Regenerate

```bash
/workspace/venv-sf/bin/python tools/gen_fixtures.py
/workspace/venv-sf/bin/python tools/gen_autoexposure_fixtures.py
```

Options:

```bash
/workspace/venv-sf/bin/python tools/gen_fixtures.py --out /tmp/fixtures
```

Requirements: the Python virtualenv that has `spektrafilm` installed
(`/workspace/venv-sf`). If `spektrafilm` is not importable, the script falls
back to `SPEKTRAFILM_SRC` (default `/workspace/spektrafilm/src`).

The generators never write outside the selected output directory and never
modify the upstream checkout.

## What is captured

The upstream pipeline is a small topology with six taps:

```
rgb_in ──▶ log_e_film ──▶ cmy_film ──▶ log_e_print ──▶ cmy_print ──▶ rgb_out
```

For every parameter case the script runs
`spektrafilm.runtime.pipeline.SimulationPipeline` once per tap
(`process(img, inject="rgb_in", collect=<tap>)`) and stores the raw arrays.

### Files

| File | Content |
|---|---|
| `slice1_common.json` | everything shared by all cases: wavelengths, CMFs, illuminant spectra, colour matrices, the digested film/print profile data, the hanatos2025 tc LUT and the test image |
| `slice1_defaults.json` | case 1 |
| `slice1_camera_ev_plus1.json` | case 2 |
| `slice1_print_exposure_and_filter_shifts.json` | case 3 |
| `slice1_dir_couplers_inactive.json` | case 4 |
| `slice2_common.json` | everything the slice 2 cases share: the spectral sampling, the illuminants, the colour matrices, the CAM16-UCS samples, the two input images and the enlarger data |
| `slice2_defaults.json` | slice 2 case 1 |
| `slice2_srgb_input.json` | slice 2 case 2 |
| `slice2_camera_ev_minus1.json` | slice 2 case 3 |
| `slice2_output_gamut_off.json` | slice 2 case 4 |
| `slice4_catalog.json` | the whole catalogue of the upstream engine: the 128 printed looks (16 negatives × 8 print media) and the 20 direct scans, with the digest of every case |
| `slice5_spatial.json` | the spatial effects: the ten parameter cases (the upstream defaults, every deterministic effect alone and all of them at once), the textured 32 × 32 test image and the reference of the image space helpers |
| `slice6_stochastic.json` | the stochastic effects: the 16 cases (four stocks × four images), the 64 × 64 test images (a flat patch and a textured one), the parameters of every case and the **summary statistics** of the grain and of the glare over 12 upstream realisations (against the two upstream samplers for the grain) |
| `autoexposure_common.json` | the 320 × 240 deterministic image in linear ProPhoto and encoded sRGB, both complete upstream 192 × 256 previews, and 16 EV records (7 methods + unknown × 2 I/O variants) |
| `autoexposure_pipeline_off.json` | full upstream control run with `auto_exposure=False` |
| `autoexposure_pipeline_center_weighted.json` | full upstream run with `auto_exposure=True` and the default `center_weighted` method |
| `autoexposure_pipeline_compensation.json` | full upstream run with center-weighted AE plus `exposure_compensation_ev=+0.75` |

The original `gen_fixtures.py` total is ≈ 2.5 MB (slice 1: ≈ 972 KiB, slice 2:
≈ 232 KiB, slice 4: ≈ 378 KiB, slice 5: ≈ 1.06 MB). The focused AE fixtures
are ≈ 39.8 MB because they retain three full-resolution 320 × 240 tap sets and
two complete upstream previews.

The script runs the cases **serially**: the numba kernels of the upstream
engine use the GNU OpenMP threading layer and a `multiprocessing` pool
deadlocks when the workers are forked after the kernels have been compiled
in the parent process (`--processes 1` is the default and does not use a
pool at all).

### The slice 2 fixtures

The slice 2 fixtures run the **whole** upstream pipeline, injected at
`rgb_in`, and store **every** tap — `log_e_film` included. They are the
ground truth of the camera stage (the hanatos 2025 spectral upsampling), of
the input / output colour space handling and of the output gamut
compression.

### The cases

| Case | Input | Output gamut compression | What it exercises |
|---|---|---|---|
| `defaults` | `linear_prophoto` | `cam16ucs` | the upstream defaults, end to end |
| `srgb_input` | `srgb_encoded` | `cam16ucs` | an sRGB encoded phone photo (`input_color_space = "sRGB"`, `input_cctf_decoding = True`) |
| `camera_ev_minus1` | `linear_prophoto` | `cam16ucs` | `camera.exposure_compensation_ev = -1.0` (the enlarger re-normalises the print exposure) |
| `output_gamut_off` | `linear_prophoto` | `off` | isolates the CAM16-UCS output compressor |

Every other parameter is the base configuration above (all the spatial and
stochastic effects off, the input gamut compression at the upstream default
`xy`).

### The shared file

`slice2_common.json` carries:

* `spectral` — the wavelengths and the CIE 1931 2° colour matching
  functions;
* `illuminants` — the TH-KG3, D55, D50 and D65 spectra, the scan illuminant
  and its normalisation, and its chromaticity;
* `color` — the reference illuminant chromaticity (D55), the ProPhoto RGB →
  XYZ matrix of the filming stage, the XYZ → sRGB matrix of the scanning
  stage and the sRGB → sRGB matrix of the output transfer function;
* `cam16ucs` — the viewing conditions (`L_A`, `Y_b`), the white point and a
  set of samples with their `Jpab` (the forward model) and their compressed
  sRGB values (the output gamut compressor);
* `input_images` — the two camera images (`linear_prophoto`, `srgb_encoded`);
* `enlarger` — the illuminant of the enlarger and the transmittance of the
  CMY dichroic filters.

The hanatos 2025 tc LUT is the one of `slice1_common.json` (it only depends
on the film sensitivity, the hanatos 2025 adaptation and the input gamut
compression).

## The CPU auto-exposure fixtures

Regenerate only this family with:

```bash
/workspace/venv-sf/bin/python tools/gen_autoexposure_fixtures.py
```

For a quicker metering-only regeneration (which skips the three full pipeline
runs), append `--metering-only`; `--out /tmp/ae-fixtures` selects another output
directory. The normal command writes all four files listed above under
`Tests/FilmPhysicsTests/Fixtures/`.

The deterministic linear ProPhoto image is 320 × 240, with a bright off-centre,
dark edges and colour gradients, so every method has a distinct EV and the
long-edge downscale is exercised. The encoded variant is clipped to [0, 1] and
sRGB encoded. `autoexposure_common.json` records all seven upstream method
names — `average`, `median`, `center_weighted`, `partial`, `matrix`,
`multi_zone`, `highlight_weighted` — plus an unknown-name fallback, on **both**
I/O variants. Each record includes the colourspace, CCTF-decoding flag, EV and
preview shape. The complete outputs of unmodified
`ResizingService.small_preview(image)` (default `max_size=256`, order 0) are
stored for sampling diagnostics.

The three pipeline files run the unmodified `SimulationPipeline` with Portra
400 → Portra Endura, grain and the other spatial / stochastic effects off, and
DIR couplers active per pixel. They store `rgb_in`, `log_e_film`, `rgb_out`, the
digested parameters, measured AE EV / scale, camera-compensation scale and both
print-balance mid-grey references. This makes the AE / compensation ordering
and the rule `0.184 * 2 ** exposure_compensation_ev` directly testable. Earlier
slice fixtures are unchanged and continue to use `auto_exposure=False`.

## The slice 5 fixtures (the spatial effects)

The slice 5 fixtures exercise the **deterministic** spatial effects of the
upstream engine: the highlight boost, the in-emulsion scatter, the
back-reflection halation, the spatial diffusion of the DIR-coupler
inhibitors, the diffusion filters of the camera and of the enlarger, the
lens blur of the camera and the lens blur and the unsharp mask of the
scanner.

The **grain** and the **glare** are *not* part of them: the grain draws its
particles from the SciPy binomial and Poisson random variates and the glare
draws a lognormal from the unseeded NumPy random state (the upstream itself
is not reproducible there). Both are deferred to the slice 6 (below).

The test image is a 32 × 32 linear ProPhoto RGB image with a grey ramp,
saturated and skin-like patches, two highlight spots (one neutral, one warm),
a smooth gradient and a textured field separated by a hard edge.

The micrometre scale effects (the scatter, the halation and the inhibitor
diffusion) need a pixel of a meaningful size: on a 32 × 32 image a 35 mm
frame gives a pixel of 1093.75 µm, i.e. every one of those effects is below
one pixel (and therefore a mathematical no-op). The cases that exercise them
therefore use a **1 mm film format** (31.25 µm per pixel) and, for the
scatter, the `scatter_spatial_scale` knob of the upstream.

| Case | What it exercises |
|---|---|
| `baseline` | every spatial effect switched off (the reference of the single effect cases) |
| `defaults_grain_off` | the upstream defaults, with the grain (and the glare) off |
| `halation` | the in-emulsion scatter and the back-reflection halation |
| `highlight_boost` | the boost that reconstructs the pre-clip irradiance |
| `dir_coupler_diffusion` | the spatial diffusion of the DIR-coupler inhibitors |
| `camera_diffusion_filter` | the diffusion filter of the camera (the black pro mist family) |
| `enlarger_diffusion_filter` | the diffusion filter of the enlarger |
| `camera_lens_blur` | the lens blur of the camera |
| `scanner_blur_unsharp` | the lens blur and the unsharp mask of the scanner |
| `all_effects` | every deterministic spatial effect at once |

The file also carries the reference of the image space helpers (the `helpers`
block): the separable FIR Gaussian, the Young & van Vliet IIR Gaussian, the
exponential filter (the Gaussian mixture surrogate) and the `reflect`
boundary of the upstream kernels.

## The slice 6 fixtures (the stochastic effects)

The slice 6 fixtures exercise the two **stochastic** effects of the upstream
engine: the grain of the negative and the veiling glare of the print.

Neither of them can be reproduced bit for bit, so the fixture stores their
**summary statistics** over **12 upstream realisations** instead of the
fields:

* the upstream grain reseeds the global legacy NumPy random state with a
  fixed seed per channel and sub layer (`[0, 1, 2]`, `+ 10` per sub layer),
  so the upstream grain is deterministic; the fixture **shifts** those seeds
  by `1000 · (seed + 1)` to measure the spread of the upstream — the
  algorithm is not touched;
* the upstream glare draws from the **unseeded** global NumPy random state,
  so the fixture seeds it (`numpy.random.seed(seed)`) before every run.

The statistics of a field are the ones the Swift port computes as well: the
mean and the standard deviation of every channel (`mean_c`, `std_c`), the
autocorrelation of the centred field at the lags 1, 2, 3, 5 and 8 (`acf_l`,
the horizontal and the vertical neighbours pooled), the correlation of the
three channels (`corr_i_j`) and the quantiles 5 %, 25 %, 50 %, 75 % and 95 %
of the density histogram (`qXX`, the three channels pooled).  Every case
stores the statistics of the 12 realisations and their aggregate (the mean,
the spread, the minimum and the maximum).

The grain is stored **twice** per case: against the default upstream path
(the exact SciPy `poisson` and `binom` generators) and against the fast
path (`settings.use_fast_stats = True`, the normal approximations of
`spektrafilm.utils.fast_stats`, the kernels the Swift port reproduces).  The
difference between the two aggregates measures the error of the normal
approximation of the fast samplers.

The cases use a **1 mm film format** (a pixel of 15.6 µm on the 64 × 64
images): the amplitude of the shot noise of the emulsion scales with one
over the square root of the number of particles a pixel holds, i.e. with the
area of the pixel, so a 35 mm frame would make the grain a mathematical
no-op on a 64 × 64 image.

The fixture is generated **serially**, like every other slice (the numba
kernels of the upstream engine use the GNU OpenMP threading layer and a
`multiprocessing` pool deadlocks when the workers are forked after the
kernels have been compiled in the parent process).

## Number format

* All floating point values are rounded to **7 significant digits**.
* `NaN` is written as JSON `null`. Upstream
  (`spektrafilm.utils.conversions.density_to_light`) turns NaN densities into
  zero light transmittance, so `null` means "no contribution".
* Wavelength-indexed arrays are `[wavelength][cmy]`, images are
  `[height][width][3]`.
* The hanatos2025 tc LUT is stored as base64 (little endian float32, C order)
  to keep the file small; its SHA-256 is stored next to it.

## Parameter cases

All cases share the same base configuration (see the `params` block of every
fixture file for the *digested* values that were actually used).

**Base configuration — every spatial and stochastic effect is switched off:**

| Upstream field | Value | Meaning |
|---|---|---|
| `camera.auto_exposure` | `False` | no image-dependent metering |
| `camera.lens_blur_um` | `0.0` | no lens blur |
| `camera.diffusion_filter.active` | `False` | no camera diffusion filter |
| `enlarger.lens_blur` | `0.0` | no enlarger lens blur |
| `enlarger.diffusion_filter.active` | `False` | no enlarger diffusion filter |
| `scanner.lens_blur` | `0.0` | no scanner blur |
| `scanner.unsharp_mask` | `(0.0, 0.0)` | no unsharp mask |
| `scanner.white_correction` / `black_correction` | `False` | no black/white correction |
| `film_render.grain.active` | `False` | no stochastic grain |
| `film_render.halation.active` | `False` | no scatter / halation |
| `film_render.glare.active` | `False` | no film glare |
| `print_render.glare.active` | `False` | no print glare |
| `print_render.density_curves_morph.active` | `False` | no print-curve morph (upstream default) |
| `film_render.dir_couplers.active` | `True` | **kept**: the chemical coupling is part of the film |
| `film_render.dir_couplers.diffusion_size_um` | `0.0` | …but its spatial diffusion is off, so it is per pixel |
| `io.output_gamut_compress.algorithm` | `"off"` | no output gamut compression (diagnostic build) |
| `io.input_gamut_compress` | upstream default | `active=True`, `algorithm="xy"`, `knee=(0.0, 1.0, 6.0)` — kept |
| `io.scan_film` | `False` | print-and-scan, not direct scan |
| `settings.use_enlarger_lut` / `use_scanner_lut` | `False` | exact spectral path, no 3D LUT approximation |

**Cases**

1. `defaults` — the base configuration.
2. `camera_ev_plus1` — `camera.exposure_compensation_ev = +1.0`.
3. `print_exposure_and_filter_shifts` — `enlarger.print_exposure = 1.3`,
   `enlarger.y_filter_shift = +10.0`, `enlarger.m_filter_shift = -5.0`
   (Kodak CC units, added to the neutral CC values that
   `digest_params` reads from the upstream `neutral_print_filters.json`).
4. `dir_couplers_inactive` — `film_render.dir_couplers.active = False`.

## Test image

A deterministic 12×12 linear ProPhoto RGB image:

* row 0 — neutral grey ramp, log spaced `0.002 … 2.0`;
* row 1 — saturated colour patches;
* row 2 — skin-like colour patches;
* rows 3…11 — seeded random block (`numpy.random.default_rng(1234)`), log
  spaced `0.001 … 4.0`.

The image is stored in `slice1_common.json` under `test_image`.

## Digested data

Besides the taps, every case file carries the derived data the Swift port
needs but that is not recoverable from the raw profile JSON:

* `neutral_filters_cc` — the neutral CC filter values after the upstream
  database lookup, plus the shifted values;
* `enlarger.filtered_illuminant_spectrum` — the TH-KG3 illuminant after the
  CC filters;
* `print_balance.density_spectral_midgray` / `…_comp` — the print-balance
  reference computed by the filming stage (and its exposure-compensated
  variant);
* `enlarger.exposure_factor_midgray` / `…_comp` / `exposure_factor_used` —
  the print exposure normalisation factors;
* `print_black_white_reference` — the black/white references used by the
  printing stage;
* `dir_couplers.matrix` and `density_curves_before_couplers` — the DIR
  coupler inhibition matrix and the film density curves *before* the
  couplers are applied;
* `camera_exposure_scale`, `pixel_size_um`.

The shared file carries the digested profile data (log exposure, density
curves, density curve layers, channel/base density, the fitted CDF model),
the illuminant spectra, the CIE 1931 2° CMFs, the colour matrices
(ProPhoto RGB → XYZ(D55), XYZ → sRGB, the sRGB → sRGB matrix used by the
output transfer function) and the hanatos2025 tc LUT.

## Verification

The fixtures were checked against the upstream engine by re-implementing the
stage maths from the fixture contents alone (film development, print exposure,
print development and scanning). Every stage reproduces the upstream taps to
≈ 1e-6, i.e. the rounding floor of the 7-significant-digit format.
