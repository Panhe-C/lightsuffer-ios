# PORTING.md — spektrafilm → Swift (slices 1 and 2)

Status: **slice 1 and slice 2 ported and validated** (2026-11-09).

This document is the map between the upstream Python engine
([spektrafilm](https://github.com/andreavolpato/spektrafilm) @ `3bb2c2d`, GPLv3)
and the pure-Swift `FilmPhysics` package of this repository.

* Upstream reference tree: `/workspace/spektrafilm/src/spektrafilm` (read only).
* Reference fixtures: `Tests/FilmPhysicsTests/Fixtures/slice1_*.json` and
  `slice2_*.json`, generated by `tools/gen_fixtures.py` from the **unmodified**
  upstream engine.
* Bundled upstream data tables: `Sources/FilmPhysics/Resources/` (packed by
  `tools/pack_resources.py`, provenance in
  `Sources/FilmPhysics/Resources/CHANGELOG.txt`).
* The Swift port is a derivative work and is distributed under the GPLv3 as
  well (see `LICENSE`, `NOTICE`).

## 1. What the slices cover

### 1.1 Slice 1 — everything after `log_e_film`

The upstream topology has six taps:

```
rgb_in ──▶ log_e_film ──▶ cmy_film ──▶ log_e_print ──▶ cmy_print ──▶ rgb_out
```

Slice 1 ports everything **after** `log_e_film`:

| Stage | Upstream | Swift | State |
|---|---|---|---|
| spectral upsampling (camera) | `runtime/stages/filming.py` → `utils/spectral_upsampling.py` | — | **not ported** (the tap is injected) |
| negative development | `runtime/stages/filming.py::develop` → `model/develop.py::develop` | `Pipeline.swift::developFilm` | ported |
| DIR couplers | `model/couplers.py` | `Couplers.swift` | ported (per pixel, no diffusion) |
| printing (exposure) | `runtime/stages/printing.py::expose` | `Pipeline.swift::exposePrint`, `Printing.swift`, `Enlarger.swift` | ported |
| printing (development) | `runtime/stages/printing.py::develop` → `model/develop.py::develop_print_morph` | `Printing.swift::develop` | ported (morph inactive) |
| scanning | `runtime/stages/scanning.py::scan` | `Scanning.swift` | ported (no blur / unsharp / glare) |
| output gamut compression | `utils/gamut_compression.py::compress_rgb` | — | **not ported** (`"off"` in the slice 1 fixtures) |
| profile loading | `profiles/io.py` | `Profile.swift` | ported |
| parameter digest | `runtime/params_builder.py::digest_params` | `Digest.swift` | ported (film specifics) |

Public entry point:

```swift
let pipeline = try Slice1Pipeline(film: film, print: print, inputs: inputs)
let taps = try pipeline.run(logEFilm: image)   // -> cmyFilm, logEPrint, cmyPrint, rgbOut
```

Public entry point:

```swift
let pipeline = try FilmPipeline(params: params)
```

The pipeline validates its parameters and **throws** on the features that are
not ported yet (`FilmPipeline.init`): the direct film scan, the auto
exposure, the lens blurs, the unsharp mask and the `mallett2019` RGB → raw
method.

## 3. Numerical fidelity notes

### 3.1 Slice 1

The port follows the upstream code line by line. The points that needed care:

1. **`fast_interp` is not `numpy.interp`.** The upstream kernel
   (`utils/fast_interp.py`) uses a per channel axis
   (`log_exposure[:, None] / gamma_factor`), clamps the values outside the
   axis, is right biased on the axis knots and gives a zero slope to
   duplicated axis entries. `DensityCurves.interpolateExposureToDensity`
   reproduces all of it; `Numerics.interpolate` reproduces the plain
   `numpy.interp` used by the DIR coupler inversion (clamping, exact knot
   values, `NaN` in → `NaN` out).
2. **`numpy.interp` on a non monotonic axis.** The DIR coupler inversion
   interpolates on `log_exposure - inhibitors`, which is ascending for every
   shipped profile (verified for Portra 400 in `ProfileLoaderTests`). The
   Swift implementation follows the `numpy.interp` semantics for an
   ascending axis.
3. **The normal CDF.** `scipy.stats.norm.cdf` is reproduced with
   `erf`/`erfc` built on the regularised incomplete gamma function
   (series + continued fraction). The agreement with SciPy is ≤ 1e-14
   (`NumericsTests.testNormalCDF`).
4. **`NaN` handling.** The upstream profiles store the missing measurements as
   `NaN` (JSON `null`); the Swift loader maps `null` to `Double.nan`.
   `density_to_light` turns a `NaN` density into *no* light, `nan_to_num`
   turns the `NaN` sensitivities into zero — both reproduced.
5. **The XYZ → RGB matrix of the scanning stage.** `colour.XYZ_to_RGB`
   applies the CAT02 adaptation **to the input** and then the (unadapted)
   sRGB matrix. The reference fixture stores the resulting matrix the way
   `colour.XYZ_to_RGB(identity, …)` returns it, i.e. **row `i` is the RGB
   response to the `i`-th XYZ basis vector**; the port therefore converts
   with the row vector product `rgb = xyz · matrix`. (The note of the fixture
   calls it `rgb = result @ xyz`, which is the transposed convention — the
   *data* is right, the wording of the note is not.)
   The sRGB → sRGB matrix of the output transfer function is applied the
   other way round (`rgb = matrix · rgb`), exactly like
   `colour.RGB_to_RGB`.
6. **The sRGB matrices** are the rounded ones of `colour-science`
   (`3.2406, -1.5372, …`), so that the Lab conversion of the port agrees
   with the upstream engine to the last digits.
7. **The print development uses the fitted CDF model**
   (`utils/morph_curves._evaluate_fitted_density`), not the stored density
   curves — the stored curves are only used by the black/white reference of
   the print, exactly as upstream.

### 3.2 Slice 2

1. **The hanatos 2025 lookup table.** The upstream builds a 192 × 192 × 3
   table over the chromaticity (`tc.x`, `tc.y`) of the scene: the spectrum of
   the table (`irradiance_xy_tc.npy`, float16) is weighted by the log
   sensitivity of the film and by the normalised band pass window of the
   adaptation. The port rebuilds the table from the same three ingredients
   (the bundled float16 spectrum, the profile sensitivity and the window of
   the profile) — the measured agreement is **2.4e-7 relative**.
2. **The lookup is a Mitchell–Netravali cubic** (`B = C = 1/3`) on a
   *reflected* border (`SpectralUpsampling.lookup`), not a bilinear
   interpolation.
3. **The input gamut compression is baked into the table**, the way the
   upstream does it (`remap_tc_lut_for_compression`):
   `new_lut[xy] = old_lut[compress(xy)]`. The compression itself is a radial
   Reinhard knee against the polygon of the spectral locus
   (`compress_xy_radial`).
4. **The chromatic adaptation is computed, not loaded.** The filming stage
   adapts the ProPhoto primaries to the reference illuminant of the film
   (D55) with **CAT16** (the upstream `_rgb_to_tc_b` calls
   `colour.RGB_to_XYZ(..., chromatic_adaptation_transform="CAT16")`); the
   scanning stage adapts the scan illuminant to the sRGB white point with
   **CAT02** (the default of `colour.XYZ_to_RGB`); the sRGB → sRGB matrix of
   the output transfer function is the **CAT02** round trip of
   `colour.matrix_RGB_to_RGB(sRGB, sRGB)` (its default transform; the
   reference fixture stores the `1.182393e-16` entry of that very matrix).
5. **The bundled spectral tables are `float32`.** The illuminant spectra and
   the CMFs are narrowed from double to float32 when they are packed (the
   hanatos irradiance table keeps its upstream float16 payload verbatim).
   That costs ≈ 1e-7 relative on the chromaticity of the reference
   illuminant, which is the floor of the colour matrix parity: the `Z` row
   of the ProPhoto matrix is a *difference of larger terms*, so its relative
   error reaches 1.3e-6 while its absolute error stays at 1.9e-9.
6. **The CAM16-UCS output compressor** builds its own table of the maximum
   in-gamut chroma (64 lightness samples × 720 hues, 18 bisection steps, the
   same `numpy.linspace` grids as the upstream) and compresses the chroma
   with a Reinhard knee; the lightness is compressed one-sided with the
   white point of the output colourspace as the reference.
7. **The print balance reference is computed by the port.** The 0.184 grey
   patch is upsampled in **sRGB without CCTF decoding** (the default of the
   upstream helper), whatever the input colourspace of the pipeline is, and
   developed with the *un-normalised* density curves of the film — the
   upstream subtlety reproduced in `Filming.densitySpectralMidgray`.

## 5. Measured errors

The Swift pipeline is fed with the `log_e_film` tap of the reference fixtures
(slice 1) or with the camera image `rgb_in` (slice 2) and every tap is
compared with the reference.

Reference fixtures are stored with **seven significant digits**, so the
rounding alone is worth ≈ 1e-6 — the measured errors sit exactly on that
floor.

### 5.1 Slice 1 (the tap by tap parity)

| Case | `cmy_film` (max abs) | `log_e_print` (max abs) | `cmy_print` (max abs) | `rgb_out` (max abs) | `rgb_out` mean ΔE₀₀ | `rgb_out` max ΔE₀₀ |
|---|---|---|---|---|---|---|
| `defaults` | 1.0417e-06 | 7.2062e-07 | 7.0010e-07 | 2.2302e-04 | **0.002450** | 0.010716 |
| `camera_ev_plus1` | 8.8654e-07 | 5.2414e-07 | 7.4257e-07 | 2.2052e-04 | **0.002413** | 0.010677 |
| `print_exposure_and_filter_shifts` | 1.0417e-06 | 5.6148e-07 | 7.4609e-07 | 2.1097e-04 | **0.002296** | 0.009934 |
| `dir_couplers_inactive` | 6.6316e-07 | 3.5987e-07 | 7.0996e-07 | 1.2006e-04 | **0.001938** | 0.007900 |

### 5.2 Slice 2 (the whole pipeline, from `rgb_in`)

| Case | `log_e_film` (max abs) | `cmy_film` (max abs) | `log_e_print` (max abs) | `cmy_print` (max abs) | `rgb_out` (max abs) | `rgb_out` mean ΔE₀₀ | `rgb_out` max ΔE₀₀ |
|---|---|---|---|---|---|---|---|
| `defaults` | 6.1795e-07 | 5.8378e-07 | 4.9565e-07 | 5.7025e-07 | 9.6892e-05 | **0.002065** | 0.007997 |
| `srgb_input` | 5.3384e-07 | 4.9786e-07 | 1.7426e-07 | 7.8151e-07 | 9.8541e-05 | **0.001984** | 0.007957 |
| `camera_ev_minus1` | 5.8241e-07 | 5.3940e-07 | 2.4218e-07 | 8.6249e-07 | 9.4721e-05 | **0.002094** | 0.007757 |
| `output_gamut_off` | 6.1795e-07 | 5.8378e-07 | 4.9565e-07 | 5.7025e-07 | 2.2297e-04 | **0.002450** | 0.010722 |

The `output_gamut_off` case is the slice 1 `defaults` case: with the output
gamut compression switched off, the port reproduces the slice 1 numbers
(mean ΔE₀₀ 0.002450 — the `rgb_out` error differs in the sixth digit only,
because the slice 1 test injects the *rounded* `log_e_film` tap of the
fixture while the slice 2 test computes it).

The ΔE₀₀ numbers are computed on the **sRGB encoded output clipped to
[0, 1]**, converted to CIELAB (D65) and compared with the Sharma et al.
(2005) CIEDE2000 formula.

Gates implemented in `Tests/FilmPhysicsTests/Slice1ParityTests.swift` and
`Tests/FilmPhysicsTests/Slice2ParityTests.swift`:

* mean ΔE₀₀ < 0.5 (the acceptance criterion of the plan) — **measured
  ≈ 0.0020 – 0.0025**;
* tightened: mean ΔE₀₀ < 0.01 and max ΔE₀₀ < 0.05;
* tap wise: max abs error < 5e-6 for `log_e_film`, `cmy_film`,
  `log_e_print`, `cmy_print` (the plan asked for 1e-3).

Other measured quantities:

| Quantity | Measured |
|---|---|
| exposure factor (defaults) | 0.8357499920608669 vs. 0.8357499 (reference) |
| print black reference (`log_raw_print_black`) | max abs error 2.15e-08 |
| print white reference (`log_raw_print_white`) | max abs error 3.29e-07 |
| profile data vs. the digested fixture data | max relative difference ≤ 1e-6 (7 digit rounding) |
| DIR coupler inhibitor matrix | max relative difference ≤ 1e-6 |
| density curves before the couplers | max relative difference ≤ 1e-6 |
| fitted print density curves | max relative difference ≤ 1e-6 |
| CIEDE2000 vs. the 33 published Sharma pairs | ≤ 1e-4 (the published precision) |
| hanatos 2025 tc LUT (192 × 192 × 3) | max relative error **2.3881e-07**, max abs error 2.1301e-06 |
| CAM16-UCS forward model | max abs error **2.5009e-05** |
| CAM16-UCS round trip | max abs error **1.1102e-15** |
| output gamut compressor (`cam16ucs`) | max abs error **4.8076e-08** |
| colour matrices (D55 chromaticity, ProPhoto → XYZ) | max relative error **1.3123e-06** (the `Z` row of the matrix, absolute error 1.93e-09) |

The colour matrices are compared with a **relative tolerance of 1e-6**
(the rounding of the seven significant digits of the fixtures) and an
absolute floor of 1e-8, which covers the entries that come out of a
cancellation of larger terms (see §3.2, point 5).
